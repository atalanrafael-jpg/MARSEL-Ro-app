# ДЕЙСТВУЙ — единая каноническая система MARSEL / RO App

Дата контрольной точки: 2026-08-22
Каноническая ветка: `act/marsel-unified-system-2026-08-22`
База: `main` на SHA `268d8ad47039ad2b6257ff97ce6ccdbf0e54d14e`

## 1. Назначение

Единая система для Ювелирной студии MARSEL, работающей в одном контуре Ro App, с тремя направлениями услуг:

1. ювелирные изделия и их ремонт;
2. ремонт и обслуживание часов;
3. ремонт и обслуживание очков.

Очки добавлены как отдельное направление ремонта. Это не означает, что старые данные RO App автоматически получают новые категории или услуги.

## 2. Источник истины

Приоритет источников:

1. текущий код и конфигурация этой канонической ветки;
2. актуальная официальная документация RO App;
3. фактические результаты CI этой ветки;
4. канонические документы MARSEL;
5. исторические ветки и старые результаты — только для происхождения и поиска причины дефекта.

Исторические материалы не являются текущим состоянием.

## 3. Правила проекта

- Работа продолжается только в этой канонической ветке до отдельного решения о смене контрольной точки.
- Старые ветки не сливаются автоматически.
- Старые данные не копируются в рабочие справочники автоматически.
- API endpoint считается подтверждённым только после проверки актуальной документацией или фактическим контрактом.
- Аудит RO App — read-only, пока отдельно не разрешена операция записи.
- Нельзя создавать очередные версии скрипта только ради обхода предыдущей ошибки.
- Каждый новый объект должен иметь одно каноническое место хранения.
- Закрытая задача не возвращается в работу без нового доказательства.

## 4. Единая модель приложения

Общие сущности системы:

`Клиент → Изделие/объект → Заказ-наряд → Диагностика → Смета → Согласование → Работа → Материалы/запчасти → Контроль качества → Выдача → Оплата → Гарантия/история`

Направление услуги определяется полем/справочником `service_domain`, а не отдельной независимой системой.

Допустимые значения первой версии:

- `JEWELRY` — ювелирные изделия;
- `WATCH` — часы;
- `EYEWEAR` — очки.

## 5. Разделение предметной области

### JEWELRY

Материал, проба, масса, вставки, размеры, конструктивные особенности, ремонтные операции, оценка и контроль результата.

### WATCH

Бренд, модель, механизм, серийный номер при наличии, тип механизма, состояние, комплектность, диагностика, ремонтные операции и контроль хода.

### EYEWEAR

Бренд/модель при наличии, тип оправы, материал оправы при известности, линзы, дефекты, комплектность, диагностика, ремонтные операции и контроль результата.

Для EYEWEAR не следует автоматически применять ювелирные поля металла/пробы/вставок или часовые поля механизма.

## 6. Единый заказ-наряд

Каждый заказ-наряд имеет:

- уникальный ID;
- клиента;
- одно или несколько изделий/объектов;
- `service_domain` для каждого объекта;
- описание проблемы;
- фото/вложения при наличии;
- диагностику;
- согласованную смету;
- материалы/запчасти;
- исполнителя;
- этап;
- стоимость;
- оплату;
- гарантию;
- журнал событий.

## 8. Экономика

Общие правила:

- работа учитывается отдельно от материалов/запчастей;
- себестоимость и продажная цена не смешиваются;
- для ювелирного направления отдельно учитываются металл и вставки;
- для часов и очков учитываются соответствующие запчасти и расходные материалы;
- маржинальность считается по заказу и направлению;
- валюта проекта — RUB.

## 9. Данные и безопасность

Персональные данные, финансовые данные и данные клиентов не переносятся из старых веток в новую систему без подтверждения необходимости и происхождения.

Регуляторные материалы (ФНС, Федеральная пробирная палата, Роскомнадзор и другие) хранятся как проектные требования/справочная база до отдельного разрешения на регистрацию, отправку или публикацию.

## 10. Что считается готовностью

Готовность не определяется наличием файлов. Требуется одновременно:

- единая модель данных;
- единая предметная модель трёх направлений;
- подтверждённые RO App API-контракты;
- отсутствие необоснованных дубликатов;
- тесты;
- актуальный CI;
- read-only audit без скрытых write-операций;
- документированная контрольная точка;
- воспроизводимый результат проверки.
