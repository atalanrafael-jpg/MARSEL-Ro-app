# 05 — План сборки единой системы

## Phase 0 — Контрольная точка

- Зафиксировать HEAD канонической ветки.
- Проверить, что ветка не отстала от `main`.
- Не использовать старые ветки как рабочую базу.

## Phase 1 — Инвентаризация

Проверить только текущую каноническую ветку:

- `app/`
- `scripts/`
- `tests/`
- `.github/workflows/`
- `02_ROAPP/`
- master-документы
- зависимости

Для каждого объекта: `KEEP / MERGE / ARCHIVE / REMOVE / VERIFY`.

## Phase 2 — API Contract

Проверить по актуальной официальной документации RO App:

- authentication;
- orders;
- clients;
- catalog/products;
- warehouses;
- goods/stock;
- payments, если API поддерживает;
- другие необходимые read endpoints.

Для каждого контракта хранить доказательство. Неподтверждённый endpoint не используется в production logic.

## Phase 3 — Общая бизнес-модель

Реализовать единый контур:

`Customer → ServiceOrder → ServiceObject → Diagnosis → Estimate → Work → Materials/Parts → QC → Delivery → Payment → Warranty`.

## Phase 4 — Домены

### JEWELRY

Добавить только подтверждённые поля и услуги ювелирного направления.

### WATCH

Добавить только подтверждённые поля и услуги часового направления.

### EYEWEAR

Добавить профиль очков, каталог работ и запчастей. Не создавать отдельную клиентскую или заказ-нарядную систему.

## Phase 5 — Каталоги

Единые справочники:

- услуги;
- материалы;
- запчасти;
- статусы;
- причины;
- способы оплаты;
- сотрудники;
- склады.

Доменная классификация используется для фильтрации.

## Phase 6 — UI / формы

Одна форма приёма с выбором направления и динамическими специализированными полями.

Одна карточка заказа-наряда.

Один журнал событий.

Один механизм сметы и согласования.

Один механизм выдачи и гарантии.

## Phase 7 — Quality & Security

- unit tests;
- contract tests;
- read-only integration tests;
- duplicate checks;
- data quality checks;
- security checks;
- CI gates.

## Phase 8 — Live validation

Только read-only:

1. получить текущие данные;
2. сравнить со схемой;
3. проверить пагинацию;
4. проверить идентификаторы;
5. сформировать evidence;
6. не изменять live данные.

## Phase 9 — Production Gate

Production readiness возможна только после прохождения всех обязательных gates текущего commit.

Старые CI runs не используются для PASS текущей ветки.

## Phase 10 — Controlled write

Write-интеграции рассматриваются только после отдельного согласования и подтверждения API-контрактов. До этого система остаётся read-only в отношении live Ro App.

## Критерий завершения

Система считается собранной только когда архитектура, модель данных, API-контракты, код, тесты, CI и документация описывают одну и ту же систему без противоречий.
