# 02 — Единая предметная модель

## Основные сущности

```text
Customer
  └── ServiceOrder
        ├── ServiceObject
        │     ├── JewelryProfile
        │     ├── WatchProfile
        │     └── EyewearProfile
        ├── Diagnosis
        ├── Estimate
        ├── WorkItem[]
        ├── MaterialItem[]
        ├── Payment[]
        ├── QualityCheck
        ├── Delivery
        └── Warranty
```

## Customer

Минимальный единый профиль клиента. Контакты и персональные данные хранятся один раз. Дубликаты клиентов не создаются из-за разных направлений услуг.

## ServiceOrder

Заказ-наряд является главным бизнес-объектом. Он содержит общий статус и ссылки на объекты ремонта.

Обязательные контрольные поля:

- `id`
- `customer_id`
- `created_at`
- `service_domain`
- `status`
- `estimated_total`
- `currency=RUB`

## ServiceObject

Представляет физический объект клиента.

Общие поля:

- `id`
- `order_id`
- `domain`
- `description`
- `condition_at_intake`
- `completeness`
- `photos`
- `serial_or_external_identifier` при наличии

## JewelryProfile

Поля применяются только при `domain=JEWELRY`:

- металл;
- проба;
- масса;
- вставки;
- размеры;
- конструктивные признаки;
- особенности состояния.

## WatchProfile

Поля применяются только при `domain=WATCH`:

- бренд;
- модель;
- механизм;
- серийный номер при наличии;
- корпус;
- стекло;
- браслет/ремешок;
- комплектность;
- состояние.

## EyewearProfile

Поля применяются только при `domain=EYEWEAR`:

- бренд;
- модель;
- тип оправы;
- материал оправы при известности;
- цвет/отделка;
- тип линз при известности;
- состояние линз;
- носоупоры;
- заушники;
- крепления;
- комплектность.

## Diagnosis

Диагностика фиксирует наблюдаемый дефект, причину только когда она подтверждена, необходимые работы и риски.

Нельзя превращать предположение мастера в подтверждённый факт.

## Estimate

Смета разделяет:

- работу;
- материалы;
- запчасти;
- дополнительные услуги;
- скидки;
- итог.

## WorkItem

Каждая операция имеет:

- услугу;
- количество;
- цену;
- исполнителя;
- статус;
- фактическое время, если поддерживается Ro App.

## MaterialItem

Материалы и запчасти связываются с заказом и, если API позволяет, со складским движением.

Для ювелирного направления стоимость металла и вставок не смешивается с оплатой работы.

## QualityCheck

Перед выдачей фиксируются результаты контроля. Для разных направлений используются разные чек-листы, но единый механизм статуса.

## Delivery

Фиксирует выдачу клиенту, дату, ответственного и итоговый статус.

## Warranty

Связывает гарантию с конкретным заказом и выполненными работами. Срок и условия не должны выдумываться системой: используются только утверждённые условия MARSEL.

## Очки — отдельный модуль, не отдельная система

`EYEWEAR` использует тот же Customer, ServiceOrder, Diagnosis, Estimate, WorkItem, MaterialItem, Payment, QualityCheck, Delivery и Warranty.

Отдельным является только профиль объекта и специализированный каталог услуг/запчастей.

## Принцип нормализации

Один факт хранится один раз. Если значение используется несколькими направлениями, оно находится в общей сущности. Если значение специфично для направления, оно находится в профильной сущности.
