# MARSEL — РЕМОНТ ОЧКОВ

## Назначение
Ремонт очков добавляется в MARSEL как самостоятельное направление услуг, связанное с единым контуром клиентов, заказов, материалов, склада, сотрудников, оплаты и аналитики.

## Приём изделия
Для каждого заказа фиксируются:
- клиент;
- тип изделия: очки/оправа/солнцезащитные очки и др. — только если фактически поддерживается каталогом;
- производитель и модель при наличии;
- описание изделия и состояния;
- видимые дефекты;
- комплектность;
- фотографии при необходимости;
- заявленная клиентом неисправность;
- дата приёма;
- ответственный сотрудник;
- согласованный срок;
- предварительная стоимость, если применимо.

Неизвестные сведения не заполняются догадкой.

## Диагностика
Перед ремонтом фиксируются:
1. результат осмотра;
2. необходимые работы;
3. необходимые детали/материалы;
4. риски или ограничения ремонта;
5. итоговая согласованная стоимость;
6. согласование клиента, если оно требуется процессом.

## Типовой жизненный цикл
`Принято → Диагностика → Ожидание согласования → Ожидание детали → В работе → Контроль качества → Готово → Выдано → Закрыто`

Фактические статусы должны соответствовать активному справочнику MARSEL/ROAPP; этот список является операционной моделью, а не утверждением о наличии таких статусов в API.

## Учёт затрат
Раздельно учитывать:
- детали;
- материалы;
- труд;
- прочие подтверждённые расходы.

Себестоимость ремонта не должна смешиваться с себестоимостью изготовления ювелирных изделий.

## Склад
Детали и материалы для ремонта очков должны иметь однозначный идентификатор и единицу учёта. Списание выполняется только через подтверждённую складскую операцию. До подтверждения API-контракта ROAPP любые production-write операции остаются запрещёнными.

## Контроль качества
Перед выдачей проверяются выполненные работы, состояние изделия после ремонта и соответствие заказу. Результат контроля должен быть связан с заказом.

## Выдача
При выдаче фиксируются:
- статус заказа;
- дата выдачи;
- оплата/статус оплаты;
- ответственный;
- подтверждение передачи согласно действующему процессу.

## KPI направления
После появления достаточного массива фактических данных рассчитываются:
- количество принятых ремонтов;
- количество завершённых ремонтов;
- средний чек;
- выручка;
- подтверждённая себестоимость;
- валовая маржа;
- средний срок ремонта;
- доля просроченных заказов;
- повторные обращения;
- доля заказов, ожидающих детали.

До загрузки фактических данных MARSEL значения KPI не выдумываются.

## Интеграция с единой системой
Ремонт очков должен использовать общий контур:
`Клиент → Заказ → Изделие → Диагностика → Работы/материалы → Склад → Оплата → Контроль качества → Выдача → Аналитика`.

## Definition of Done
Направление считается внедрённым только после подтверждения:
- структуры данных;
- справочников;
- статусов;
- прав доступа;
- складского учёта;
- расчёта себестоимости;
- тестов;
- CI;
- фактического результата в ROAPP;
- post-write verification, если запись в production будет разрешена.
