Текущий рабочий контур: **ремонт ювелирных изделий**. Производство и продажи не активируются этим пакетом.

## 11. Правила качества данных

- Один клиент — одна основная карточка.
- Телефон хранится в нормализованном формате.
- Нельзя создавать дубль клиента при совпадении подтверждённого телефона.
- Нельзя удалять кандидата на дубль автоматически.
- Перед объединением сохраняются исходные ID и журнал операции.
- Сумма заказа хранится как денежное значение, а не как свободный текст.
- Ответственный сотрудник должен ссылаться на реальный ID сотрудника RO App.
- Статус должен ссылаться на реальный ID статуса RO App.
- Налоговый профиль операции не выводится из названия услуги автоматически без подтверждённого правила.

## 12. Правило внедрения

Этот документ является целевой структурой. Перед записью в RO App необходимо:

1. GET списка существующих справочников;
2. получить реальные ID;
3. сопоставить существующие значения с целевыми;
4. сформировать dry-run;
5. получить отчёт о конфликтах;
6. сделать backup;
7. только после этого выполнять разрешённые CREATE/UPDATE операции.
