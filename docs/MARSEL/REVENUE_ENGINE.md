# MARSEL — DAILY REVENUE ENGINE

## Objective
Создать повторяемый ежедневный процесс: данные → приоритетные действия → контакт → заказ → оплата → повторная продажа.

## Revenue streams
1. Ремонт ювелирных изделий.
2. Ремонт часов.
3. Изготовление изделий на заказ.
4. Продажа готовых изделий.
5. Дополнительные услуги после диагностики/ремонта.
6. Повторные продажи существующим клиентам.

## Daily queue
Каждый рабочий день система должна формировать приоритеты:
- готовые заказы, ожидающие контакта;
- просроченные заказы;
- клиенты без следующего действия;
- незавершённые обращения;
- повторные предложения;
- товары с высоким остатком;
- товары/услуги с подтверждённой высокой маржинальностью;
- потенциальные индивидуальные заказы;
- клиенты, которым требуется сервисное напоминание.

## Funnel
`Просмотр/рекомендация → обращение → консультация → расчёт → заказ → оплата → выдача → повторный контакт → повторная продажа/рекомендация`

## KPI
Использовать только фактические данные MARSEL/RO App:
- leads;
- qualified leads;
- consultations;
- orders;
- paid orders;
- average order value;
- gross margin;
- repeat purchase rate;
- lead-to-order conversion;
- order-to-payment conversion;
- revenue by service;
- revenue by product category;
- overdue orders;
- unresolved customer contacts.

## Safety
Никакие цены, маржи, конверсии или прогнозы не должны считаться фактическими без подтверждённых исходных данных.
