# MARSEL — БИЗНЕС-ПЛАН И ОПЕРАЦИОННАЯ ИНСТРУКЦИЯ

**Статус:** canonical working document. Фактические финансовые показатели не выдумываются; до загрузки первичных данных финансовые цели остаются параметрами для расчёта.

## 1. Бизнес-модель

Ювелирная студия MARSEL работает по четырём подтверждённым направлениям: изготовление и продажа ювелирных изделий, ремонт ювелирных изделий, ремонт часов и ремонт очков. Проект предусматривает развитие интернет-магазина и единого операционного контура ROAPP.

## 2. Клиентский путь

Лид/обращение → клиент → консультация → заказ → спецификация изделия/ремонта → расчёт материалов и работ → согласование → резерв материалов → изготовление/ремонт → контроль качества → оплата → выдача/доставка → закрытие заказа → сервис/повторное обращение.

Каждый этап должен иметь ответственного, статус, дату и связь с заказом.

## 3. Каталог

Создаётся Master Catalog с единым идентификатором изделия или услуги. Минимальные сущности: изделие/услуга, категория, направление, материал/металл, проба, камень, детали, вес, размеры, себестоимость, цена, фото, статус, складская позиция, канал продаж. Дубликаты идентификаторов и конфликтующие карточки блокируются до reconciliation.

## 4. Производство ювелирных изделий

Для заказа на изготовление фиксируются: клиент, изделие, техническое задание, материалы, камни, комплектующие, плановая и фактическая трудоёмкость, этапы производства, контроль качества, итоговая себестоимость и цена. Нельзя списывать материал без документируемой операции.

## 5. Ремонт ювелирных изделий

При приёме фиксируются клиент, изделие, состояние, дефекты, комплектность, фото/описание, согласованные работы, оценка стоимости, сроки и ответственный. При выдаче фиксируются результат, оплата и подтверждение передачи.

## 6. Ремонт часов

Используется отдельный процесс: марка/модель, идентификатор/серийный номер при наличии, состояние, заявленная неисправность, диагностика, согласование работ, детали, сроки, исполнитель, контроль качества и выдача. Часы не смешиваются с ювелирным ремонтом в аналитике затрат.

## 7. Ремонт очков

Используется отдельный процесс: клиент, тип изделия, производитель/модель при наличии, состояние, дефекты, комплектность, фотографии при необходимости, заявленная неисправность, диагностика, необходимые работы и детали, согласованная стоимость, срок и ответственный. После ремонта выполняются контроль качества и документируемая выдача. Очки не смешиваются с ювелирными изделиями и часами в аналитике затрат.

Рекомендуемая операционная модель статусов: `Принято → Диагностика → Ожидание согласования → Ожидание детали → В работе → Контроль качества → Готово → Выдано → Закрыто`. Этот список является моделью процесса; наличие конкретных статусов в API ROAPP должно быть отдельно подтверждено.

## 8. Склад и себестоимость

Раздельно учитываются металлы, камни, детали и комплектующие, готовые изделия, изделия в работе и позиции клиента. Себестоимость каждого направления должна быть декомпозирована как минимум на материалы и работы; дополнительные расходы включаются только при наличии фактического основания.

Для ремонта часов и очков детали должны иметь однозначный идентификатор и единицу учёта. Списание выполняется только через подтверждённую складскую операцию.

## 9. Продажи и интернет-магазин

До включения автоматической синхронизации необходимо подтвердить API-контракты товаров, услуг, остатков, заказов, статусов и идентификаторов. Затем: READ-ONLY inventory → dry-run → reconciliation → idempotency test → controlled write → post-write verification → rollback test. При отсутствии доказанного контракта запись запрещена.

## 10. Оплата и заказ

Заказ является центральной сущностью продаж и сервисных работ. Для каждого платежа должны быть сумма, валюта, способ, дата, статус и связь с заказом. Несогласованные платежи не должны автоматически считаться выручкой.

## 11. Управленческие KPI

Считать только из фактических данных: выручка, количество заказов, средний чек, валовая маржа, себестоимость материалов, трудозатраты, срок выполнения, просрочки, загрузка сотрудников, точность остатков, повторные клиенты, стоимость привлечения клиента и результат по каналу.

Формулы:
- **Средний чек** = выручка / количество закрытых продаж.
- **Валовая маржа** = выручка − подтверждённая себестоимость.
- **Маржинальность** = валовая маржа / выручка × 100%.
- **Точность остатков** = совпадающие фактические и системные позиции / проверенные позиции × 100%.

KPI должны иметь разрез по четырём направлениям: ювелирные изделия, ювелирный ремонт, часовой ремонт, ремонт очков.

## 12. Финансовое управление

Еженедельно контролировать продажи, себестоимость, дебиторскую задолженность, незавершённые заказы, склад, возвраты и денежные поступления. Ежемесячно формировать отчёт по четырём направлениям бизнеса.

Цены, бюджеты рекламы и план прибыли нельзя фиксировать без фактической статистики MARSEL.

## 13. Маркетинг

Каждое обращение получает источник. Для канала фиксируются расходы, лиды, заказы, выручка и валовая маржа. Каналы сравниваются по стоимости привлечения и фактической прибыли, а не только по числу обращений.

## 14. Автоматизация

### Автоматизировать
- ежедневные READ-ONLY проверки качества данных;
- поиск дублей;
- контроль orphan/reference ошибок;
- контроль product-code collisions;
- контроль складских остатков;
- подготовку управленческих KPI;
- CI-тестирование;
- сохранение test evidence;
- контроль зависимостей и активных entrypoints;
- сервисные напоминания по ремонтам после подтверждения бизнес-правил.

### Не автоматизировать без отдельного gate
- массовое изменение данных ROAPP;
- удаление записей;
- списание материалов;
- изменение цен;
- публикацию товаров;
- изменение остатков;
- отправку маркетинговых событий с персональными данными.

## 15. Организационная модель

Для текущей конфигурации MARSEL: одна точка и три сотрудника. Для каждого процесса назначается владелец, исполнитель и контрольная роль. Права доступа должны соответствовать фактическим обязанностям.

## 16. План развития

### Этап 1 — Data Foundation
Единый каталог, справочники, клиенты, заказы, материалы, склад, четыре направления ремонтов/продаж, роли.

### Этап 2 — Quality Control
Полный read-only audit, reconciliation, duplicate/reference/collision controls и CI evidence.

### Этап 3 — Sales & E-commerce
Интернет-магазин, платежи, доставка, marketplace preflight и подтверждённая синхронизация.

### Этап 4 — Analytics
Фактическая экономика по каждому направлению, сотруднику, изделию, услуге и каналу.

### Этап 5 — Automation
Алерты, повторные продажи, сервисные напоминания, автоматические отчёты и controlled agents.

## 17. Definition of Done для бизнеса

Процесс считается внедрённым только когда есть: структура данных, ответственный, инструкция, тест/контроль, фактический результат, журнал изменений и возможность восстановить состояние.

## 18. Главный принцип

**Не оптимизировать неизвестное. Сначала измерить, затем проверить, затем изменить, затем подтвердить результат.**
