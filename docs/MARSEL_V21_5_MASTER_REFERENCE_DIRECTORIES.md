# MARSEL V21.5 — MASTER-справочники

Статус: проектная спецификация. Не является автоматическим импортом в RO App.

## 1. Клиенты и контрагенты

Типы: физическое лицо, корпоративный клиент, постоянный клиент, новый клиент, поставщик, подрядчик, партнёр.

Связи: клиент → заказы → изделия → ремонты → оплаты → возвраты → гарантии → обращения.

## 2. Виды работ и услуг

Ювелирные: ремонт, изменение размера, пайка, лазерная сварка, полировка, закрепка, замена камня, изготовление, родирование, чистка, диагностика, оценка.

Часовые: диагностика, замена батарейки/аккумулятора, регулировка, замена стекла, ремешка/браслета, механизма, обслуживание механизма, ремонт корпуса, браслета, проверка герметичности.

Карточка услуги: услуга → категория → операция → длительность → квалификация → материалы → запчасти → стоимость → гарантия.

## 3. Причины обращения

Ремонт; изготовление; изменение размера; замена детали; замена камня; профилактика; чистка; диагностика; оценка; консультация; повторное обращение; гарантийный случай.

## 4. Статусы заказа

Новый → Принят → Диагностика → Согласование → Ожидание материала/запчасти → В работе → Контроль качества → Готов → Клиент уведомлён → Выдан → Закрыт.

Дополнительные статусы: отменён; отказ клиента; технически невозможен; ожидает оплаты; гарантийный ремонт.

## 5. Причины задержки

Нет запчасти; нет материала; ожидание поставщика; ожидание согласования; клиент не отвечает; сложность ремонта; повторная диагностика; переделка; неисправность оборудования; иная подтверждённая причина.

## 6. Гарантия

Тип: работа / запчасть / изделие.

Поля: срок; дата начала; дата окончания; условия; исключения; гарантийный случай; негарантийный случай.

Фактический срок гарантии не задавать без утверждённой политики MARSEL.

## 7. Причины отказа/отмены

Цена; срок; техническая невозможность; отсутствие детали; клиент передумал; клиент не согласовал работы; клиент не предоставил материал; другой исполнитель; иная подтверждённая причина.

## 8. Дефекты

Ювелирные: царапина; вмятина; деформация; трещина; скол; износ; разрыв; ослабление закрепки; выпадение камня; неисправность замка; износ шарнира; повреждение покрытия.

Часовые: остановка; неточный ход; повреждение стекла; корпуса; заводной головки; кнопки; календаря; хронографа; автоподзавода; нарушение герметичности.

Дефект ≠ причина брака. Эти справочники не объединять.

## 9. Причины брака

Ошибка мастера; дефект материала; дефект камня; дефект запчасти; ошибка сборки; нарушение технологии; повреждение при обработке; неисправность оборудования; неизвестная причина.

## 10. Каналы обращения

Телефон; мессенджер; сайт; интернет-магазин; социальная сеть; личное обращение; повторное обращение; рекомендация.

## 11. Каналы продаж

Студия/мастерская; интернет-магазин; заказ; повторная продажа; партнёр; маркетплейс — только при фактическом использовании.

## 12. Способы оплаты

Наличные; банковская карта; перевод; онлайн-оплата; предоплата; постоплата; смешанная оплата; сертификат; зачёт металла клиента.

Использовать только фактически подключённые способы оплаты.

## 13. Скидки и основания скидки

Программа лояльности; постоянный клиент; акция; повторный заказ; комплексная услуга; индивидуальное согласование; компенсация; гарантийный случай.

Обязательная аудитируемая связь: кто разрешил → дата → причина → размер.

## 14. Мастера и компетенции

Мастер → специализация → операция → уровень компетенции → оборудование → доступ.

Специализации: ювелир; закрепщик; часовщик; полировщик; мастер лазерной сварки; иные фактически используемые роли.

## 15. Синонимы и нормализация

Синонимы используются для поиска и выявления потенциальных дублей, но не должны автоматически объединять карточки.

Примеры: батарейка/элемент питания; ремешок/ремешок для часов; карабин/замок-карабин.

Правило: автоматическое объединение запрещено; требуется подтверждение.

## 16. Источники данных

RO App; MARSEL; поставщик; ручной ввод; импорт; API; инвентаризация; документ.

Для записи: источник → дата получения → дата последней синхронизации → идентификатор источника, если доступен.

## 17. История изменения данных

Типы: создано; импортировано; исправлено; объединено; архивировано; восстановлено; скорректировано инвентаризацией.

Хранить: дата/время; пользователь/система; причина; исходное значение; новое значение — только если это поддерживается и допустимо системой.

## 18. Рекомендации по архитектуре

Не смешивать:
- клиента и контрагента с товарной карточкой;
- услугу с технологической операцией;
- дефект с причиной брака;
- статус заказа со статусом складской позиции;
- канал обращения с каналом продажи;
- синоним с фактическим дублем.

Все реальные поля, статусы, методы оплаты и системные сущности RO App должны подтверждаться фактической конфигурацией/API перед импортом.

## 19. Quality Gate V21.5

Проверять:
1. уникальность ID/артикула;
2. дубли клиентов;
3. дубли услуг;
4. некорректные статусы;
5. отсутствующие обязательные связи;
6. невалидные способы оплаты;
7. некорректные гарантии;
8. конфликтующие синонимы;
9. источник и дату данных;
10. отсутствие write-операций в read-only тестах.

## 20. Принцип безопасности

V21.5 не создаёт и не изменяет реальные записи RO App. Это master-справочник для последующего mapping. Любая запись в RO App выполняется только после подтверждения соответствующей API-сущности, dry-run и отдельного контроля изменений.
