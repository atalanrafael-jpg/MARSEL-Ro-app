# MARSEL — карта автоматизации и контроля

## Текущий бизнес-контур

**Только ремонт ювелирных изделий.**

Все сценарии производства новых изделий, продажи, интернет-магазина, ремонта часов, изготовления на заказ и скупки не являются текущими операционными процессами MARSEL и должны быть выключены/архивированы, если они были созданы ранее. Исторические данные не удалять без резервной копии и отдельного решения.

## P0 — безопасность и соответствие

1. READ-ONLY API inventory.
2. API data contract.
3. Полный аудит пагинации.
4. Резервная копия/экспорт до любой записи.
5. Dry-run изменений.
6. Дубли клиентов, заказов, услуг и ремонтных карточек.
7. Проверка обязательных полей.
8. Контроль ГИИС ДМДК/УИН/именника для применимых операций.
9. Раздельные маршруты ремонта без изменения и с изменением существенных характеристик.
10. Журнал всех изменений.
11. Контроль массы ДО/ПОСЛЕ.
12. Контроль фото ДО/ПОСЛЕ.
13. Контроль приема и выдачи клиентского изделия.

### Юридико-технический контроль

или

`С ИЗМЕНЕНИЕМ СУЩЕСТВЕННЫХ ХАРАКТЕРИСТИК — ТРЕБУЕТ ПРОВЕРКИ`

При втором варианте выдача блокируется до выполнения предусмотренных процедур.

## P1 — финансовая аналитика ремонта

Считать по каждому заказу:

`цена ремонта − работа − материалы − расходники − комиссия − налоги − прочие прямые расходы = операционная прибыль заказа`

Показатели:

- средний чек ремонта;
- прибыль на заказ;
- валовая маржа;
- маржа по типу ремонта;
- маржа по мастеру;
- стоимость материалов;
- среднее время ремонта;
- прибыль за час мастерской;
- доля срочных ремонтов;
- доля переделок;
- доля рекламаций;
- повторные обращения;
- дебиторка;
- неоплаченные заказы;
- залежавшиеся изделия клиентов.

## P2 — автоматические события

`новое обращение → задача ответить`

`прием изделия → создать заказ-наряд`

`диагностика завершена → сформировать смету`

`смета изменена → запросить подтверждение клиента`

`согласование получено → поставить в очередь мастеру`

`срок приближается → уведомить ответственного`

`срок нарушен → эскалация руководителю`

`ремонт завершен → контроль качества`

`контроль пройден → уведомить клиента`

`выдача → закрыть заказ + гарантийный контроль`

`гарантийный случай → отдельный маршрут рекламации`

## P2 — контроль ГИИС ДМДК

Для применимых операций хранить:

- УИН;
- статус;
- идентификатор партии/операции, если применимо;
- именник;
- клеймо;
- масса до/после;
- действие по клеймению;
- дату;
- подтверждающий документ.

Не считать автоматически любой ремонт освобожденным от требований ГИИС ДМДК: решение зависит от фактической операции и изменения существенных характеристик.

## P2 — контроль прибыли и цель 3 млн руб.

Цель 3 000 000 руб. чистой прибыли в месяц должна рассчитываться только после учета всех расходов.

Ключевая формула:

`чистая прибыль = выручка ремонта − прямые затраты − ФОТ − налоги − аренда − реклама − комиссии − прочие расходы`

Система должна показывать, сколько заказов и какой средний чек необходимы для целевого результата при фактической марже MARSEL.

Не использовать целевую сумму как предположение о достижимости — сначала собрать реальные показатели.

## Что не включать в текущую автоматизацию

- производство новых изделий;
- продажа готовых изделий;
- интернет-магазин;
- маркетплейсы;
- ремонт часов;
- изготовление на заказ;
- скупка ювелирных изделий и лома.

## Что нельзя автоматизировать без дополнительного подтверждения

- изменение налогового режима;
- юридически значимая передача данных в государственные системы;
- массовое удаление/объединение записей;
- изменение УИН или иных идентификаторов;
- автоматическое изменение массы металла;
- автоматическое проведение операций в ГИИС ДМДК;
- автоматическое изменение юридических реквизитов.

## Правило внедрения

`AUDIT → BACKUP → DRY-RUN → APPROVAL → WRITE → VERIFY → REPORT`

Любая WRITE-операция должна иметь доказуемую причину, журнал до/после, автора, время, основание и возможность повторной проверки.
