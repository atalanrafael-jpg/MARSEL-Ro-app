# MARSEL V21.2 — Inventory Taxonomy & RO App Mapping

## Цель

Единая схема классификации складских позиций MARSEL для подготовки к RO App. Документ не является прямым импортом и не изменяет рабочую базу RO App.

## 1. Верхний уровень

| Код | Тип позиции | Назначение |
|---|---|---|
| FG | Изделие | Готовое изделие MARSEL для продажи |
| MAT | Материал | Металл, камни и другие материалы производства |
| CON | Расходный материал | Материалы, расходуемые при выполнении работ |
| DET | Деталь | Конструктивный элемент изделия |
| SPR | Запчасть | Сменный компонент ремонтируемого изделия/часов |
| TLS | Инструмент | Многоразовый рабочий инструмент |
| EQP | Оборудование | Производственная/диагностическая установка |

## 3. Обязательная семантика

`тип позиции` отвечает на вопрос «что это по назначению», `категория` — «к какому классу относится», `группа` — «к какому подмножеству», `вид` — «какая конкретная разновидность», `артикул` — «какая конкретная складская позиция».

Запрещается использовать категорию как замену типу позиции и наоборот.

## 4. Единицы учёта

- Изделия: шт., если фактическая операция RO App использует такую единицу.
- Камни: шт. и/или масса — только по фактической модели учёта.
- Металлы: масса (например, г), если такая единица доступна в фактической конфигурации.
- Расходники: фактическая единица закупки/расхода (шт., уп., мл, г и т. п.) — только по реальному учёту.
- Детали/запчасти: шт., если позиция учитывается поштучно.
- Инструменты/оборудование: шт. с серийным учётом при необходимости.

## 5. Складская логика

- WH001 — Основной склад
- WH002 — Производство
- WH003 — Готовые изделия
- Z01 — Драгоценные металлы
- Z02 — Камни
- Z03 — Часовые детали и запчасти
- Z04 — Расходные материалы
- Z05 — Незавершённое производство
- Z06 — Готовые изделия

Клиентские изделия не смешивать с собственными товарами MARSEL; при адресном хранении выделять отдельные ячейки.

## 6. Контроль качества данных

Перед импортом/синхронизацией проверить:
1. уникальность артикула;
2. уникальность штрихкода, если используется;
3. отсутствие дублей названий внутри одного типа;
4. отсутствие смешивания MAT/CON/DET/SPR/TLS/EQP;
5. наличие категории и группы;
6. единицу измерения;
7. стоимость только из подтверждённого источника;
8. минимальный остаток только из подтверждённой настройки;
9. серийность только там, где она реально нужна;
10. адрес хранения только для реально существующих складов/ячеек.

## 7. RO App mapping

RO App официально описывает складской учёт товаров, материалов и инструментов, категории, остатки, закупочную/розничную/ремонтную стоимость, списания, инвентаризации, минимальные остатки, серийный учёт и адресное хранение. Для ювелирного направления RO App также заявляет учёт украшений, камней, граммов металла, этикеток/штрихкодов и клиентских изделий.

Следовательно, MARSEL использует эту классификацию как внутреннюю бизнес-схему, а перед API-импортом выполняется mapping каждого поля к фактически доступному полю RO App. Нельзя предполагать наличие отдельного системного типа `деталь`, `инструмент` или `оборудование`, пока это не подтверждено API/аккаунтом.
